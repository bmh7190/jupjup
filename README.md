# JupJup (줍줍)

사용자의 자연어를 이해하고 요청 목적에 따라 경찰청 Open API를 선택 호출해 가능성이 높은 습득물 후보를 추천하는 LangChain Agent입니다. CLI와 FastAPI 기반 웹 채팅 화면을 제공합니다.

## 이번 구현 범위

1. Agent가 대화에서 검색 조건을 파악하고 필요한 정보를 추가 질문
2. 일반 검색에서는 `search_lost112_candidates` Tool로 습득물 API 2종만 조회
3. 유사 신고 요청에서는 `search_similar_lost_reports` Tool로 경찰청 분실물 API만 조회
4. 물품명, 분류, 색상, 장소, 날짜, 특징을 이용한 설명 가능한 유사도 계산
5. 대화 Memory와 PII·재시도·호출 제한 Middleware 적용
6. 경찰민원24에 옮겨 적을 분실신고 초안 작성과 누락 항목 점검
7. 사진·상세 조회·일부 API가 실패해도 확보한 검색 결과 유지
8. 실제 경찰민원24 습득물 상세 페이지 연결

신고 제출은 사용자가 경찰민원24에서 직접 진행합니다. Agent는 계정에 접근하거나
신고를 대신 제출하지 않습니다.

## 구조

```text
src/jupjup/
├── config.py       # .env와 실행 설정
├── models.py       # Pydantic 데이터 모델
├── privacy.py      # LLM 전달 전 개인정보 마스킹
├── report.py       # 분실신고 초안·누락 항목·작성 팁 생성
├── extractor.py    # 독립 실행 가능한 LangChain 구조화 추출 체인
├── api_client.py   # 경찰청 API 3종 조회와 XML 표준화
├── matcher.py      # 유사도 계산과 추천 근거
├── vision.py       # 선택적인 습득물 사진 판정
├── service.py      # API 조회·매칭 도메인 서비스
├── agent.py        # create_agent, Custom Tool, Middleware, Memory
├── cli.py          # Agent를 사용하는 터미널 채팅 화면
├── web.py          # 같은 Agent를 브라우저 채팅 화면으로 보여주는 FastAPI 서버
├── web_assets/     # web.py가 서빙하는 정적 채팅 UI (index.html)
└── demo.py         # API 키 없는 로컬 데모
```

`경찰청 분실물정보`는 다른 사용자의 분실 신고이므로 습득물 후보와 섞지 않습니다. 사용자가 "유사한 분실 신고도 확인해줘"라고 요청할 때만 별도로 조회합니다. 실제 후보 추천에는 `경찰청 습득물정보`와 `포털기관 습득물정보`를 사용합니다.

## LangChain Agent 구성

- `create_agent`: 모델이 대화를 해석하고 Tool 호출 여부와 인자를 결정합니다.
- `@tool`: `search_lost112_candidates`가 습득물 API 2종 조회와 후보 매칭을 실행합니다.
- `@tool`: `search_similar_lost_reports`가 명시적인 요청에서만 경찰청 분실물 API를 조회합니다.
- `@tool`: `prepare_lost_report_draft`가 신고서 초안과 제출 전 체크리스트를 만듭니다.
- 신고서 작성 요청이 들어오면 검색 Tool을 닫고 신고서 Tool만 실행하며, 같은 thread의 검색·신고 대화에서 확인한 정보를 합칩니다. 물품명·분실 날짜·구체적인 장소가 부족하면 한 번에 하나씩 질문만 반환하며, 세 필수 정보가 모인 뒤에 초안을 표시합니다. 나머지 선택 정보는 입력을 강제하지 않고 개선 제안으로 안내합니다.
- `InMemorySaver`: 같은 `thread_id`의 이전 대화를 기억합니다.
- `PIIMiddleware`: 이메일, 카드번호, 휴대전화번호, 주민등록번호를 마스킹합니다.
- `ToolRetryMiddleware`: 일시적인 Tool 오류를 한 번 재시도합니다.
- `ToolCallLimitMiddleware`, `ModelCallLimitMiddleware`: 한 요청에서 불필요한 반복 호출을 막습니다.

세 Tool 모두 조회와 문서 작성만 수행하므로 외부 상태를 바꾸지 않습니다. 사용자가 초안을
직접 검토한 뒤 경찰민원24 공식 화면에서 제출합니다. 향후 실제 제출 Tool을 추가한다면
제출 직전에 `HumanInTheLoopMiddleware`를 적용해야 합니다.

## 분실신고 작성 도움

채팅에서 "분실신고서를 써줘"라고 요청하면 Agent가 다음 내용을 확인합니다.

- 필수 확인: 물품명, 분실 날짜, 구체적인 분실 장소
- 공식 서식 대응: 분실 일시·장소, 물품명·수량, 색상·크기·브랜드, 분실 경위
- 작성 품질 보완: 지역, 식별 특징, 이동 경로
- 주의사항: 개인정보 마스킹, 도난 여부, 자동차번호판 방문 신고, 제출 후 수정 불가

정보가 부족하면 가장 중요한 항목부터 다시 질문합니다. 정보가 모이면 복사 가능한 초안과
누락 목록, 개선 방법, 경찰민원24 `신고하기` 직접 연결 주소와 공식 안내 주소를 함께
반환합니다. 신고인 인적사항은 생성하지 않으며 로그인 후 사용자가 직접 확인합니다.

## 설치

```bash
cd jupjup
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
cp .env.example .env
```

`.env`에 키를 입력합니다.

```dotenv
DATA_GO_KR_SERVICE_KEY=공공데이터포털_인증키
OPENAI_API_KEY=OpenAI_API_키
OPENAI_MODEL=gpt-5.4-mini
```

`DATA_GO_KR_SERVICE_KEY`에는 공공데이터포털에서 발급받은 일반 인증키의 Encoding 또는 Decoding 값을 입력합니다. 경찰청 분실물정보·경찰청 습득물정보·포털기관 습득물정보 서비스의 활용 승인이 필요합니다. 경찰청 공통코드 조회 서비스는 사용하지 않으며, 현재 필요한 대표 물품 분류 코드는 애플리케이션에 포함되어 있습니다.

기존 `.env`가 있다면 프로젝트 루트로 옮기거나 CLI의 `--env` 뒤에 해당 파일의 절대경로를 지정할 수 있습니다. 자연어 추출과 대화에는 `OPENAI_API_KEY`가 필요합니다. 키를 Git에 커밋하지 마세요. `.env`는 `.gitignore`에 포함되어 있습니다.

검색량과 시간 제한은 다음 환경변수로 조정할 수 있습니다.

| 변수 | 기본값 | 의미 |
| --- | ---: | --- |
| `LOST112_PAGE_SIZE` | `10` | 기간 API 한 페이지에서 요청할 건수, 허용 범위 1~100 |
| `LOST112_TIMEOUT_SECONDS` | `15` | 개별 HTTP 요청의 최대 대기 시간(초) |
| `LOST112_DETAIL_LIMIT` | `5` | 출처별로 상세 정보를 추가 조회할 상위 레코드 수 |
| `LOST112_MAX_PAGES_PER_WINDOW` | `10` | 출처·날짜 구간별 최대 페이지 수 |
| `LOST112_SEARCH_BUDGET_SECONDS` | `30` | 날짜 검색 전체의 최대 실행 시간(초) |

## 실행

외부 API 없이 구조와 점수를 먼저 확인합니다.

```bash
PYTHONPATH=src python -m jupjup.cli --demo
```

실제 대화형 실행:

```bash
jupjup
```

한 문장으로 실행:

```bash
jupjup --text "어제 저녁 강남역에서 검은색 카드지갑을 잃어버렸어"
```

물품명이 있으면 확인 질문 없이 바로 조회합니다. 목적격 조사를 생략한 `어제 분당구에서 핸드폰 잃어버렸어` 같은 구어체도 검색합니다. 반대로 `강남역에서 잃어버렸어`처럼 물품명이 없으면 먼저 물품명을 질문합니다.

구조화된 전체 결과가 필요하면 `--json`을 사용합니다. CLI 출력과 JSON에는 내부 후보 점수, 신뢰도, 검색 범위와 일치 근거가 포함됩니다.

```bash
jupjup --json --text "어제 홍대에서 아이폰 잃어버렸어"
```

등록된 습득물 사진을 멀티모달 모델로 추가 평가하려면 `--vision`을 붙입니다. 사진이 없는 후보에는 적용되지 않으며 OpenAI API 비용이 발생합니다.

```bash
jupjup --vision
```

경찰민원24 사진은 애플리케이션에서 내려받아 모델에 data URL로 전달합니다. 다운로드는 HTTPS 경찰민원24 호스트와 5MB 이하 JPEG·PNG·WebP로 제한하며, 특정 사진의 다운로드나 판정이 실패해도 전체 검색 결과는 유지합니다.

## 웹 채팅 화면 (가시화)

터미널 대신 브라우저에서 시연할 수 있는 채팅 화면입니다. Agent 로직은 그대로이고,
`JupJupChatAgent.chat()` 호출 결과를 채팅 UI로 보여주기만 합니다.

```bash
python -m pip install -e ".[web]"   # fastapi, uvicorn 설치
jupjup-web
```

브라우저에서 http://127.0.0.1:8000 을 열면 채팅 화면이 뜹니다. `.env`에 실제 키가 있으면
실제 Agent가 응답하고, 키가 없거나 오류가 나면 화면 상단에 오류 메시지가 표시됩니다.
이 경우에도 입력창 옆 "데모 모드" 버튼을 누르면 `demo.py`의 예시 데이터로 후보 카드 화면을
바로 확인할 수 있습니다.

검색 결과가 있으면 모델의 중복 설명 대신 구조화된 후보 카드를 표시합니다. 카드에는 물품명, 출처, 습득일·장소, 보관처, 사진과 `상세 보기` 링크를 표시합니다. 후보 카드의 크기와 간격은 화면 폭이 바뀌어도 일정하게 유지되며 좁은 화면에서는 열 수가 줄어듭니다. 내부 점수·일치 근거·신뢰도·검색 범위는 후보 선별에는 사용하지만 현재 웹 카드에는 표시하지 않습니다.

분실신고 초안은 일반 검색 카드와 구분된 문서형 말풍선으로 표시합니다. 필수·권장 누락 항목과 작성 팁을 확인한 뒤 `경찰민원24에서 작성` 버튼으로 공식 메인을 열고 `유실물 민원 > 분실물 신고`를 선택할 수 있습니다. 자동 제출은 하지 않습니다.

같은 서버를 직접 띄우려면 다음처럼 실행해도 됩니다.

```bash
PYTHONPATH=src uvicorn jupjup.web:app --reload
```

## 점수 기준

분실일이 있으면 명칭 검색 대신 기간 검색 API를 사용합니다. 분실일을 포함한 7일 → 다음 7일 → 그 뒤 한 달 순서로 조회하며, 물품명/분류에 검색어가 포함된 습득물 후보가 누적 5개 미만일 때 다음 구간으로 확장합니다. 이는 소유권이나 브랜드 일치가 확인된 후보 수를 의미하지 않습니다. 예를 들어 2026-03-14 분실은 03-14~03-20, 03-21~03-27, 03-28~04-27입니다. 끝 날짜를 포함하며 오늘 이후 구간은 조회하지 않습니다.

기간 API는 물품명 조건을 지원하지 않아 물품 분류 코드를 요청에 함께 보내고, 반환된 명칭·분류를 다시 로컬에서 필터링합니다. 날짜가 없으면 기존 명칭 검색을 사용합니다. 경찰청 분실물의 명칭 조회 API가 오류를 반환하는 경우를 피하기 위해 정상 동작하는 분류·지역·기간 API를 사용합니다.

각 출처·구간은 `LOST112_MAX_PAGES_PER_WINDOW` 페이지까지 `LOST112_PAGE_SIZE`건씩 읽습니다. 날짜 검색은 요청 사이에 `LOST112_SEARCH_BUDGET_SECONDS`의 전체 시간 예산을 확인하고, 개별 요청은 `LOST112_TIMEOUT_SECONDS`와 남은 전체 예산 중 짧은 시간으로 제한합니다. 페이지 상한 도달은 API 실패가 아니라 일부 조회로 기록합니다. 전체 시간 제한에 도달해도 확보한 자료가 있으면 결과를 유지합니다. 일부 조회 사유는 내부 검색 결과와 CLI 진단에 보존하고 웹 채팅에는 표시하지 않습니다. 아무 자료도 얻지 못했거나 실제 API 예외가 발생한 경우에만 조회 실패로 표시합니다.

상세 정보는 모든 기간 목록을 수집한 뒤 출처별 상위 후보에 한 번만 보완합니다. 상세 조회가 실패하거나 시간이 부족해도 목록에서 확보한 후보는 유지합니다. `search_scopes`에는 기간, 완료 페이지, 확인 건수, 전체 건수, 일부 조회 사유 또는 오류를 기록합니다. 전체 건수는 물품명 필터 적용 전 API가 보고한 기간 검색 결과 수이며 실제로 내려받아 비교한 건수는 아닙니다.

이 정책은 분실일 이후 약 6주 범위를 단계적으로 탐색합니다. 그보다 나중에 습득된 물건은 이번 검색 범위에 포함하지 않으며, 날짜가 일치하더라도 강남역·샤넬 등의 조건까지 일치한다는 뜻은 아닙니다.

기본 가중치는 물품명 30%, 장소 20%, 색상 15%, 날짜 15%, 분류 10%, 특징 10%입니다. 사용자에게서 얻지 못한 항목은 점수에서 제외하고 남은 항목의 가중치를 다시 합산합니다. 따라서 빈 값을 불일치로 잘못 계산하지 않습니다.

장소가 있으면 API에서 받은 결과를 로컬에서 직접 장소 → 같은 시군구 → 인접 시군구 → 같은 시도 → 인접 시도 → 전국으로 분류하고, 후보가 발견된 가장 가까운 범위만 남깁니다. 현재 API를 지역별로 차례대로 다시 호출하는 방식은 아닙니다. 서울 주요 구는 같은 구와 인접 구를 더 세밀하게 구분합니다. 먼 지역 후보가 다른 조건만으로 과도하게 높은 점수를 받지 않도록 같은 시도 75점, 인접 시도 60점, 전국 45점의 상한을 적용합니다.

사진 판정을 켜면 상위 3개 후보 중 실제 사진이 있는 항목에만 15% 가중치를 추가합니다. CLI와 JSON에는 총점과 함께 `날짜 유사도가 높음`, `확인 가능한 습득물 사진이 있음` 같은 근거가 표시됩니다. 웹 카드는 정보 밀도를 줄이기 위해 점수와 근거를 표시하지 않습니다.

분실일보다 먼저 습득된 물건, 습득물이 아닌 다른 사람의 분실 신고, 40점 미만 후보는 추천 습득물에서 제외합니다. 다른 사람의 유사 분실 신고는 별도 참고 목록으로만 제공합니다. 습득물의 `상세 보기`는 관리번호와 순번을 사용해 경찰민원24 실제 상세 페이지로 연결합니다.

## 트러블슈팅

### `DATA_GO_KR_SERVICE_KEY가 없습니다`

프로젝트 루트의 `.env`에 `DATA_GO_KR_SERVICE_KEY`가 있는지 확인합니다. Encoding 키와 Decoding 키 모두 사용할 수 있으며 애플리케이션이 요청 전에 중복 인코딩을 방지합니다.

### `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 또는 HTTP 403

키 문자열이 틀렸거나 해당 경찰청 Open API 서비스의 활용신청이 승인되지 않은 상태입니다. 공공데이터포털에서 경찰청 분실물정보·습득물정보·포털기관 습득물정보의 활용 상태를 확인합니다. 경찰청 공통코드 조회 서비스는 현재 실행에 필요하지 않습니다.

### OpenAI 인증 실패

`.env`의 `OPENAI_API_KEY`와 `OPENAI_MODEL`을 확인합니다. 셸에 오래된 키가 설정되어 있어도 프로젝트에서 읽은 `.env` 값이 우선합니다. 키를 변경한 뒤 실행 중인 CLI나 웹 서버를 재시작합니다.

### 검색이 약 30초 후 `일부 조회`로 끝남

외부 API가 느리거나 결과가 많아 `LOST112_SEARCH_BUDGET_SECONDS`에 도달한 경우입니다. 확보한 후보가 있으면 정상적인 부분 성공으로 처리합니다. 상세 사유는 CLI에서 확인할 수 있으며, 필요하면 전체 시간 예산이나 페이지 상한을 늘릴 수 있지만 응답도 더 늦어질 수 있습니다.

### 특정 출처만 `조회 실패`로 표시됨

세 출처는 독립적으로 처리합니다. 한 출처가 실패해도 다른 출처의 후보는 유지됩니다. 모든 출처가 실패했을 때는 인증키, 활용신청 상태와 네트워크를 먼저 확인합니다.

### 물품명을 입력했는데 다시 질문함

서버가 최신 코드인지 확인하고 재시작합니다. 현재 버전은 `핸드폰을 잃어버렸어`와 `핸드폰 잃어버렸어`를 모두 즉시 검색합니다. 물품명이 실제로 없는 문장은 추가 질문이 정상입니다.

### 사진이 없거나 이미지 판정에 실패함

공공데이터에 사진이 등록되지 않은 후보가 많습니다. `--vision`은 선택 기능이며 사진 다운로드나 모델 판정이 실패해도 텍스트 기반 후보는 유지됩니다. 허용된 경찰민원24 HTTPS 이미지와 5MB 이하 JPEG·PNG·WebP만 처리합니다.

### `상세 보기`가 기본 홈페이지로 이동함

서버를 최신 `main`으로 갱신하고 재시작한 뒤 새 검색 결과에서 확인합니다. 기존 화면에 이미 출력된 카드는 자동 갱신되지 않습니다. 습득물 상세 URL에는 `pkupCmdtyMngId`와 `sortSn`이 포함되어야 합니다.

### 웹 화면이 열리지 않음

`python -m pip install -e ".[web]"`로 웹 의존성을 설치하고 `jupjup-web`을 다시 실행합니다. 상태는 다음 명령으로 확인할 수 있습니다.

```bash
curl http://127.0.0.1:8000/api/status
```

정상이면 `{"ready":true,"error":null}`이 반환됩니다. 포트가 이미 사용 중이면 기존 서버를 종료하거나 다른 포트로 `uvicorn`을 실행합니다.

### GitHub PR의 Vercel 배포가 실패함

로컬 FastAPI 실행과 Vercel 배포는 별개입니다. 현재 저장소에는 Vercel 전용 설정 파일이나 서버리스 진입점이 없으므로 연결된 Vercel 프로젝트의 자동 배포가 실패할 수 있습니다. 정확한 원인은 Vercel 프로젝트 소유자가 배포 로그에서 확인해야 합니다. Vercel에 배포하려면 Python 진입점과 빌드 설정을 별도로 구성하고 `DATA_GO_KR_SERVICE_KEY`, `OPENAI_API_KEY` 같은 비밀값은 저장소 파일이 아니라 Vercel 환경변수로 등록합니다.
