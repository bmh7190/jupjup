# 신고서 후속 대화와 조회 실패 처리

분실물 검색 후 신고서 작성을 요청하면, 이후 보완 답변과 수정도 같은 신고서 작업으로 처리한다. 이전에는 현재 문장에 `신고서 작성`이라는 표현이 없으면 Tool을 숨겨서, 초안 수정이 검색으로 바뀌거나 텍스트만 출력되는 문제가 있었다.

## 대화 처리 기준

| 입력 상황 | 처리 |
| --- | --- |
| 일반적인 분실 설명 또는 검색 요청 | 습득물 조회. 신고서 자동 생성 없음 |
| 명시적인 신고서 작성·누락 점검 요청 | 신고서 작성 시작 |
| 작성 중 물품·날짜·장소 등 보완 답변 | 확인된 정보를 합쳐 신고서 객체 갱신 |
| 작성 중 색상·크기 등 수정 요청 | 수정한 신고서 객체 반환 |
| 무관한 질문 | 신고서 Tool 호출 없이 답변 |
| 작성 취소·대화 마무리·검색으로 전환 | 신고서 후속 작성 흐름 종료 |
| 다른 `thread_id`의 대화 | 이전 대화의 작성 상태를 사용하지 않음 |

대화 이력은 기존 LangGraph 체크포인터를 사용한다. 별도의 전역 작성 플래그나 프론트 상태를 추가하지 않는다. 대화 의도와 문맥 판정은 `conversation.py`, 모델·Tool 연결은 `agent.py`, 실제 조회 성공 출처 판정은 `service.py`에서 담당한다.

의도 판정은 한국어 표현을 규칙으로 구분하므로 모든 표현을 일반화하지는 않는다. 같은 종류의 물품에 관한 완전히 새로운 분실 사건은 새 대화(`thread_id`)로 시작하면 이전 사건 정보와 명확히 분리된다.

모델이 신고 Tool 호출에서 필드를 생략하면 같은 대화의 이전 성공한 검색·신고 결과에 있는 값을 보존한다. 명시적인 `null`, 빈 문자열, 빈 목록은 그대로 적용해 삭제한 값이 다시 생기지 않도록 한다. 다른 물품의 신고를 시작하면 이전 물품의 날짜·장소를 복사하지 않는다. 모델이 보낸 Tool 인자와 성공 결과를 함께 참고하며, 실패하거나 차단된 호출은 이전 확인 정보로 취급하지 않는다.

품목을 모르는 `찾아줘` 요청에는 바로 물품명을 질문한다. 특정 물품 목록을 하드코딩하는 대신 현재 문장과 같은 대화의 이전 검색·신고 정보를 참고하며, 실제 품목 추출은 모델이 수행한다. 빈 품목으로 Tool이 호출되더라도 외부 조회 전에 차단한다.

## 조회 실패 기준

날짜가 있는 조회는 실패한 출처도 오류 범위를 보존하기 위해 빈 응답을 만든다. 이 응답을 성공적인 0건으로 해석하지 않도록, `source_counts`에는 실제 목록 페이지를 받은 출처만 포함한다. 상세 오류와 조회 범위는 기존 `errors`, `search_scopes`에 유지한다.

| 상황 | 안내/종료 코드 |
| --- | --- |
| 모든 출처의 목록 요청 실패 | 조회 실패, CLI 종료 코드 1 |
| 정상 응답이지만 결과 0건 | 후보 없음, CLI 종료 코드 0 |
| 일부 출처 성공·다른 출처 실패 | 부분 성공 결과와 오류 정보, CLI 종료 코드 0 |
| 첫 페이지 성공 후 다음 페이지 실패 | 확보한 결과와 부분 조회 범위 보존 |

`JupJupChatResponse`의 JSON 스키마와 프론트 파일은 변경하지 않는다. 신고는 계속 사용자가 공식 사이트에서 검토 후 직접 접수한다.

## 검증

2026-09-11 검증 결과:

- 최신 `main` 통합 후 전체 자동 테스트 63개 통과.
- 실제 모델 대화 27턴 통과: 기존 대화 7턴, 취소·검색 전환·무관 질문·새 대화 등 추가 16턴, 실제 API를 포함한 기본 흐름 4턴.
- 대화 기록 복원 보완 후 최종 코드에서 실제 API 기본 흐름 4턴을 재확인. 신고서 생성·수정 모두 분실 날짜·시간 유지.
- 날짜 유무와 전체 실패·성공 0건·일부 출처 실패를 조합한 독립 검증 6건 통과.
- 기존 응답 JSON 스키마와 동일하며 프론트 파일 변경 없음.
- 최신 `main`의 조사 없는 분실 설명 처리와 통합한 뒤, 해당 검색·신고서 보완 4턴을 실제 모델로 추가 확인.

외부 API를 호출하지 않는 회귀 테스트:

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src \
  .venv/bin/python -m unittest discover -s tests -v
```

실제 모델과 API를 사용하는 기본 확인:

```bash
PYTHONPATH=src .venv/bin/python -m jupjup.cli
```

같은 대화에서 다음 순서로 입력하면 검색부터 신고서 수정까지 확인할 수 있다. 분실 날짜는 실행일보다 미래가 되지 않게 지정한다.

1. `2026년 9월 10일 오후 6시에 서울 강남역에서 검정 지갑 1개를 잃어버렸어. 찾아줘.`
2. `방금 말한 내 분실 정보로 분실신고서 초안을 써줘.`
3. `검정이 아니라 파란색이야. 가로 11cm이고 흰색 스티커가 붙어 있어. 이 내용으로 수정해줘.`
4. `신고서 작성은 그만하고 방금 말한 지갑 습득물만 찾아줘.`

2~3번은 검색을 다시 실행하지 않고 신고서 객체를 반환해야 하며, 3번에서도 이미 확인한 분실 날짜와 시간이 유지되어야 한다. 별도 대화에서는 `신고서 작성 도와줘`에 이어 `어제 강남역에서 지갑을 잃어버렸어`라고 답하는 흐름도 확인한다.

실제 조회는 경찰청 API 응답과 설정된 페이지·시간 상한의 영향을 받는다. 이번 변경은 조회 시간 배분이나 상세 보강 정책을 바꾸지 않으므로, 부분 조회와 상세 생략 여부는 계속 `search_scopes`로 확인해야 한다.
